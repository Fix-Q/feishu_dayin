# 飞书多维表格 · Word 模板排版打印插件

在飞书多维表格（Bitable）侧边栏中，用你自己排好版的 **Word 模板** 打印记录数据。选中一条记录，插件把字段值填入模板对应的占位符变量，浏览器内预览后直接打印，或下载填充好的 .docx。支持关联字段循环输出成表格、按字段值自动匹配模板、模板上传/复制/删除管理。

## 核心能力

- **自定义 Word 排版**：在 Word 里排好版式，用 `{字段名}` 占位符标记数据位置，保存为 .docx 即成模板。
- **模板自动匹配**：为每个数据表指定一个“匹配字段”，打开插件或切换记录时，用该字段的值自动选中同名模板（文件名去掉 .docx 等于字段值）。
- **模板搜索/筛选**：模板下拉支持搜索；模板管理页支持按名称筛选。
- **关联字段循环**：关联字段可展开为子表记录数组，用 `{#关联字段}…{/关联字段}` 循环片段把每条关联记录输出成表格的一行。
- **变量参考面板**：列出当前表所有可用变量（系统变量、字段变量、关联字段的子字段与循环片段），一键复制粘贴进 Word。
- **模板管理**：上传、复制（快速派生新模板）、删除、下载，方便实验员维护。
- **模板按数据表隔离**：每张数据表拥有独立的模板库（`templates/<tableId>/*.docx`），只看到、只能操作自己的模板，切换数据表时自动重新加载，互不干扰。不同表可以有同名模板。
- **模板存储在项目内**：所有模板以真实 .docx 文件保存并纳入 git，本地部署即可直接调用。

## 环境要求

- Node.js 16+（建议 18+）
- npm（已提供 lock 文件）

## 快速开始

```bash
npm install

# 启动开发服务（默认端口 5173）
npm run start
# 指定端口（macOS/Linux）
PORT=5199 npm run start
# 指定端口（Windows PowerShell）
$env:PORT=5199; npm run start
```

启动后本地地址为 `http://localhost:5173/`。作为飞书插件使用时，需要一个 HTTPS 地址（见下）。

## 作为飞书侧边栏插件使用

1. 启动本地 dev server（上一步）。
2. 用内网穿透工具（如 cloudflared、ngrok）把本地端口暴露为一个 HTTPS 地址，例如：
   ```bash
   cloudflared tunnel --url http://localhost:5199
   ```
3. 在飞书多维表格的插件配置里，把插件地址填为该 HTTPS 地址。
4. 在表格中从侧边栏打开插件，选中一条记录即可打印。

> **重要**：本插件依赖 dev server 提供的 `/api` 接口（模板增删、匹配配置）与 `/templates` 静态目录（模板取源）。因此 **生产使用方式 = 常驻运行 dev server + 内网穿透**，而不是把 `dist/` 当静态站点托管（那样没有后端 API）。

## 制作模板

1. 打开“变量参考”页，点“复制全部变量”，把变量清单粘进一个空白 Word 文档作为起点。
2. 在 Word 里排好版式，把 `{字段名}` 放到需要填数据的位置。
3. 关联字段用循环片段 `{#字段名}{序号} {子字段A} {子字段B}{/字段名}`，**开始标签 `{#…}` 与结束标签 `{/…}` 必须放在 Word 表格的同一行里**，每条关联记录会自动复制成一行。
4. 另存为 .docx，到“模板管理”上传。
5. 若文件名（去掉 .docx）等于某条记录匹配字段的值，选中该记录时会自动匹配到这个模板。

### 可用变量

- **系统变量**：`{打印日期}`、`{打印时间}`、`{数据表名称}`、`{记录ID}`
- **字段变量**：`{字段名}`（普通字段直接输出显示值）
- **关联字段**：
  - 循环：`{#关联字段名}…{序号}…{子字段名}…{/关联字段名}`（放进表格同一行）
  - 汇总文本：`{关联字段名_文本}`（不写循环时输出一段逗号分隔文本）

### 说明与限制

- 取值与表格显示一致（日期、单选、多选等按界面格式输出）；复选框输出“是/否”。
- 附件字段只输出文件名，**不插入图片**。
- 字段名与系统变量重名时，以真实字段为准。
- 单个关联字段最多展开 50 条记录（超出会提示并截断）。
- 预览用于校对数据，复杂版式（文本框、浮动图片、页眉页脚）的完全保真以“下载 Word”后用 Word 打开为准。

## 构建

```bash
npm run build
```

产物在 `dist/`（仅前端资源，不含 API，见上文生产使用方式说明）。

## 目录结构

```
├── templates/              # 模板库（纳入 git）
│   ├── _config.json        # 各表的自动匹配字段配置（按 tableId）
│   ├── _legacy/            # 早期未分表的模板归档（不参与列表，可手动迁回）
│   └── <tableId>/*.docx    # 每张数据表的模板，按表隔离
├── server/
│   └── templateApi.js      # 模板/配置 API（挂载到 dev server）
├── src/
│   ├── index.tsx           # 入口
│   ├── App.tsx             # 三页签编排
│   ├── types.ts
│   ├── hooks/useActiveRecord.ts
│   ├── services/           # templateApi / dataBuilder / docxFill / templateMatch
│   ├── components/         # PrintTab / TemplateManageTab / VariablePanel / DocxPreview
│   └── utils/print.ts
├── webpack.config.js
└── package.json
```

## 常见问题

- **打印被拦截**：本插件用同源隐藏 iframe 打印，一般不会被弹窗拦截；若仍失败，改用“下载 Word”后在本地打印。
- **模板功能报“无法连接本地模板服务”**：确认 dev server 正在运行，且插件地址指向的就是这个 server。
- **自动匹配没生效**：到“模板管理 → 自动匹配设置”为当前表选一个匹配字段，并确认模板文件名与字段值一致。
